## Сервис авторизации

### 1. Граница сервиса
В сервисе авторизации — `Person`, `AuthIdentity`, сессии; в gefest — `Membership`, `Audience`, `AudienceMember`, `AccessGrant`, `Invitation`, `AccessRequest`. Правило: «кто ты» — сервис авторизации, «что тебе можно в мемориале» — gefest. Сервис авторизации выдаёт и проверяет токены, а gefest проверяет права человека в мемориале и ограничения токена. `ApiToken` убран — решение 12а.

### 2. Что в токене
В токене только «кто это» — человек, мемориал, области доступа; роли и аудитории gefest проверяет по БД на каждом запросе, иначе отзыв доступа не сработает сразу. Так устроены системы с правами на объекты (GitHub, Google Drive, Notion); роли в токене — подход корпоративного входа с немногими общими ролями.

### 3. Возврат на мемориал
Возвращаем только на хосты из `TenantHost`; одноразовый код живёт около минуты и годится одному хосту; `state` + PKCE. Как работают код и PKCE — `vk-login-pkce.md`.

### 4. Сессии
Сессия живёт час без активности: каждый запрос продлевает её, после часа простоя нужен вход заново. «Выйти» — выход из всех мемориалов: сервис авторизации закрывает свою сессию и все сессии мемориалов, выданные от неё.

### 5. Второй способ входа
Если этот Telegram уже привязан к другому человеку — запрещаем: «Этот способ входа уже используется другой учётной записью». Слияние учёток — потом. Тогда же — сверка учёток по номеру телефона из VK и Telegram: только подсказка «у вас уже есть учётная запись, вход через VK», без автоматической привязки (номера переходят к другим людям); хранится не номер, а HMAC от него.

### 6. Потеря доступа
Как владелец восстанавливает вход, если потерял VK, — отложено, подумаем потом.

### 7. Согласие на обработку данных
Храним ли, когда человек дал согласие и на какую версию политики, и что делать с его записями при удалении аккаунта, — отложено, сделаем потом. Предложение: история согласий отдельными записями в сервисе авторизации; при удалении аккаунта человек выбирает — удалить его записи или оставить без имени; единственный владелец не может удалить аккаунт, пока не назначит другого.

## Боты и их токены

Чат с платформой — только наши боты в Telegram и VK; позже, возможно, другие мессенджеры. WhatsApp не делаем: платный, сложно платить из России, под угрозой блокировки в России. Человек пишет боту в чате, бот добавляет посты в мемориал. Claude, ChatGPT и другие внешние приложения к платформе не подключаются.

Приложение бота — отдельный сервис: приём сообщений + языковая модель + MCP-клиент. В gefest бот ходит только через наш MCP-сервер. MCP-сервер — тоже отдельный сервис: даёт модели инструменты и ходит в gefest через обычный API, как фронт; gefest про MCP не знает. Почему отдельно: модели нужны крупные действия вместо мелких запросов API, опасных инструментов в MCP-сервере просто нет, нагрузка от ботов не задевает сайт.

### 8. Как бот получает токен
- Бот узнаёт человека по id отправителя сообщения (`AuthIdentity`) и получает токен у сервиса авторизации внутри системы — без ключей, без OAuth и без экрана подтверждения. Проверить при реализации: id отправителя в боте совпадает с id из входа на сайт. Решить потом: что делает бот, если человек ещё не входил на сайт.
- Защита в три слоя: модель может вызвать только инструменты MCP-сервера (опасных инструментов нет, удаление — с подтверждением в чате); токен пропускает только разрешённые области; gefest проверяет права человека.
- Новый мессенджер — новое приложение-адаптер бота и, если нужно, новый вид `AuthIdentity.provider`; MCP-сервер и права не меняются.
- Решить потом: какая языковая модель у ботов — Claude и ChatGPT по API из России недоступны.
- Ключи из настроек для своих скриптов — потом, если понадобятся.

### 9. Области доступа
`read` — читать то, что видит человек; `content` — создавать посты и контент там, куда человеку можно добавлять, менять и удалять созданное ботом; `media` — загружать файлы; `originals` — скачивать оригиналы, если это право есть у человека; `create-memorial` — создать мемориал, человек становится владельцем. Никогда: открывать контент другим, менять аудитории, участников, права и настройки, трогать не своё.

Действие бота разрешено, только если оно можно человеку (gefest проверяет роль, аудитории, выдачи) **и** у токена есть нужная область.

### 10. Привязка к мемориалу
Токен бота действует во всех мемориалах, где человек владелец (решение 11); если их несколько, бот уточняет в чате, в какой добавлять. Область `create-memorial` ни к какому мемориалу не привязана.

### 11. Кто может пользоваться ботом
Только владелец мемориала. Писать боту и добавлять через него посты может только владелец; приглашённые участники добавляют посты только на сайте. Создание мемориала через бота — по решению «Создание мемориала» в `Access.md`, кто может создавать — вопрос 23.

### 12. Срок отзыва
Токен бота живёт 5 минут. Снятие участия или роли срабатывает сразу: gefest проверяет права по БД на каждом запросе (решение 2). Изменения того, что записано в самом токене (области), срабатывают с задержкой до 5 минут, пока не истечёт уже выданный токен, — это приемлемо.

### 12а. `ApiToken` не нужен
Убираем `ApiToken` из модели: боту ключ не нужен, он узнаёт человека по аккаунту в Telegram или VK. Вместо `createdByApiTokenId` у каждого изменения хранится канал, через который оно сделано: сайт, бот Telegram, бот VK. В истории видно, например, «пост добавила Кира через бота Telegram».

## Роли и права

### 13. Главный владелец
Создатель мемориала — главный владелец. Только он назначает владельцев и снимает их; остальные владельцы этого не могут. Право главного владельца можно передать другому человеку — сделаем потом. Что делать, если главного владельца нет, — вместе с преемственностью (отложено).

### 14. Автор видит своё
Автор всегда видит то, что создал сам, даже если пост закрыт от его аудиторий.

### 15. `CONTRIBUTE` и видимость
Добавлять посты можно только в раздел, который человек видит: для добавления нужны и `CONTRIBUTE`, и `VIEW`. Само `CONTRIBUTE` раздел не открывает. Если владелец выдаёт `CONTRIBUTE` аудитории, которой раздел не открыт, сайт предупреждает: «Друзья не видят этот раздел, добавлять в него они не смогут».
